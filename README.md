# 修好了 · 华中师范大学校园报修原型

这是根据《人机交互》期末大作业学生选题报告制作的前端交互原型，覆盖学生端和维修师傅端。页面使用原生 HTML、CSS 和 JavaScript，无构建工具和第三方运行时依赖。

## 文件结构

```text
.
├── index.html        # 页面骨架、可访问性入口、脚本加载
├── styles.css        # 设计令牌、响应式布局、组件样式
├── js/
│   ├── data.js       # 学生端与维修师傅端的演示数据
│   ├── icons.js      # 统一的 SVG 图标库与图标渲染器
│   └── app.js        # 页面渲染、交互流程、弹窗与状态同步
└── README.md
```

## 运行方式

直接双击 `index.html` 即可打开。也可以在当前目录启动静态服务器：

```bash
python -m http.server 5173
```

然后访问 `http://localhost:5173`。

## 演示路径

- 首次打开会进入登录页。学生端演示账号为 `student@ccnu.edu.cn / 123456`，也支持学号 `2024214334 / 123456`；维修师傅端演示账号为 `tech@ccnu.edu.cn / 123456`，也支持工号 `WX-018 / 123456`。
- 登录页可以切换“学生端 / 维修师傅端”账号类型；角色决定进入的工作台和可见导航。注册时会保存当前浏览器的演示账号，退出登录后可以再次切换角色。
- 登录后进入对应的 APP 工作台；已经登录时不能直接切换角色，需要先点右上角账号头像退出，再登录另一类账号。
- 学生端：点击“快速报修”提交新工单；打开当前工单查看时间轴；使用“提醒后勤”；在“消息通知”和“我的报修”中查看记录。
- 维修师傅端：在任务队列打开任务，依次体验“接单 → 开始前往 → 已到达 → 开始维修 → 维修完成”；也可以提交异常上报。
- 学生端和师傅端通过本地任务池实时同步：提交新报修后，师傅端会收到“收到新报修”提示并在队列顶部看到任务；师傅更新状态后，学生端当前工单也会同步更新。同步同时使用 `localStorage`、`BroadcastChannel` 和页面重新获得焦点时的刷新机制。
- 两个端需要使用同一个地址打开（推荐都访问 `http://127.0.0.1:5173`）。直接双击 `index.html` 也能查看单端原型，但不同浏览器对 `file://` 的本地存储隔离规则不同，跨端联调时建议使用上面的静态服务器方式。

## 设计方向

一个面向华中师范大学校园的、可信且易扫描的维修服务工作台：从参考图中提取薄荷绿、雾青灰、深青绿和白色作为主色，让登录、注册和业务页面形成连续的服务体验；用琥珀色强调紧急任务，以东区八栋、南湖13栋等报告中的校园地点作为演示数据。

## 人机交互原则落地

- **可理解性**：首页把“当前工单”、地点、维修人员和进度放在同一块区域；操作按钮使用“快速报修”“查看完整进度”等结果导向的文字，图标只做辅助提示。
- **可学习性**：报修弹窗用“填写信息 → 确认提交 → 等待处理”的流程提示；地点、故障类型、维修时间和故障描述按照用户实际填写顺序分组。
- **可预见性**：学生端和师傅端使用固定的底部导航、顶部通知和角色入口；任务状态始终用文字、颜色和进度节点共同表达，避免只依赖颜色。
- **反馈**：提交报修、收到新任务、师傅更新状态、图片选择和异常上报都会给出即时提示；跨标签页同步时，学生端会收到“工单状态更新”反馈。
- **分组与映射**：地图标记对应报修位置，路线节点对应上门顺序，状态筛选对应师傅当前要处理的任务集合，帮助用户把熟悉的校园服务经验迁移到 APP 中。
- **冗余提示与容错**：关键状态同时通过时间轴、标签、提示条和 toast 呈现；上传照片为可选步骤，未选择照片仍可以完成报修。

## 内容与视觉调整

- 首页保留当前工单、状态时间轴、上门位置、常用操作和“报修前看一眼”信息块，历史记录通过“打开记录”进入独立页面。
- 师傅工作台的任务数、待接单、维修中和今日完成会根据任务队列实时计算，任务队列和今日路线分别提供不同的工作目标。
- 文案改为校园后勤中的具体动作和状态，减少宣传口号、泛化标题和不必要的英文标签；空的测试工单会在加载时清理，避免演示数据干扰界面。
- 通过手机画布容器查询修正窄屏布局，最近报修和任务卡片保持可读宽度，不会再被挤成细长列。
- 首页采用“当前任务优先”：历史工单通过“打开记录”进入独立页面，记录页默认显示最近 4 条，需要时再展开全部，减少无目的滚动。
